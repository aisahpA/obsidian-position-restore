# 00 改前必读：动手之前先看这里

`01`~`06` 讲**这段代码在干什么**；这一篇讲**动了会坏什么**。两者是不同的问题：
读懂了代码不代表知道它的约束从哪来。

- 只读代码、想弄明白机制 → 读 `01`~`06`，按目录顺序。
- **准备动手改** → 先在这一篇里查你要动的模块，然后去看它指的那一节。
- 想知道「当初为什么这么定」 → 顺着每条规则后面的 `→ detail §X` 去 AI 记忆
  （`MEMORY-detail.md`，真身在 Obsidian vault，**不进 git**）。
  ⚠️ **读不到那边的东西不影响动手**：那边只装 WHY 与实测，这一篇里的判据是完整自洽的。

**每一条规则后面都带源码位置** —— 行号会随代码漂移，§10 有一条命令能批量复查它们还准不准。

## 1. 十二条最常踩的

按「踩了会静默坏掉」排序，不按模块排。

1. **阅读模式没有「可显示的光标」，但 `editor` 一直在。**
   `MarkdownView.editor` 恒存在（`setMode` 只搬 `scroll` + `fold`，**从不碰 selection**）⇒
   阅读模式 `setCursor` 是有效的。`src/position/ui/cue.ts:114` 附近那句「阅读模式没有光标，所以永远用
   最顶上那个已渲染的块」只对了一半（它谈的是**渲染出来的块**，不是 `editor` 对象）——
   **照它写的 `getMode()` 守卫是错的**。→ detail §61

2. **切模式 / resize 会把落点打回**（`2be6916`，手机 + 电脑都复现）。
   根因在 app：`setMode(e){ i=this.scroll; … e.setEphemeralState({scroll:i}) }` 携带的是
   **own 字段 `view.scroll`** 而非 DOM；填它的是 `syncScroll()`，而**阅读模式的 `onScroll` 有
   100ms 渲染门** ⇒ 我们直接写 `scrollTop` 永远进不去。
   **修法只有一条路**：`syncViewScroll(view)` 在 `holdEdge` 之后（bracket 内）调
   `view.setEphemeralState({scroll})` —— 与 `setMode` 同一扇门。
   ⚠️ 别对阅读模式做「读 DOM 再写回去」。→ detail §63

3. **编辑模式下别去 `scrollIntoView` 光标** —— core 自己在 `setState` 时还原原滚动，你那样做会打架。

4. **`leaf.id` 跨会话稳定。** 布局序列化带着 id，重启后恢复出来的每个标签页还是原来那个 id。
   ⇒ 持久化的 `entry.leafId` 重启后仍指得着那个标签页。
   ⚠️ **别加「重启后按 path 找 leaf」的兜底** —— 会盖掉「回到它当时所在的那个标签页」这条刻意语义。→ detail §6（定案 22）

5. **`FileView` 没有 `file` 不算目的地**，否则删文件那一瞬会铸出 `view:markdown` 幽灵行。
   ⚠️ 别用「什么不是地点」那道黑名单（`NON_DESTINATION_VIEW_TYPES`，`src/nav/entry.ts:82`）堵
   —— 那道门与栈共用。→ detail §6（定案 20）

6. **一落点 = 一记录**（2026-09-26 起）。合并发生在 `settle()` 里的 `absorbSameLanding`
   （`src/recent-files/places.ts:648`，`:345` 处调用），保留 newest。
   **「一行 ≠ 一地点」已作废** —— 那是从前的前提。
   `landingKeys` 那个集合接口仍留着，但它是显示层口径的安全网，现在几乎总是只有一个元素。→ detail §2

7. **搜索 / 块引用命中的落点不进最近文件**（降级成 visit），**但后退栈照记**。
   规则只写在 `NavPlaces` —— funnel / stack / patcher **不动**。判据共享在 `src/nav/entry.ts`
   （`isCallerKey:124` / `isBlockKey:161` / `blockAnchor:145` / `stripLinkAlias:132`），
   别再手写 `startsWith('caller:')`。→ detail §6（定案 23）、§2

8. **`prop[: value]` 只认自有属性**（`hasOwnProperty`）。用 `in` 会让 `toString` / `constructor`
   命中每一篇笔记。⚠️ 别用 `Object.hasOwn`（tsconfig 的 lib 是 es2021）。
   **属性名区分大小写**；选择器要取 `getAllPropertyInfos()` 的 **`values().name`** ——
   那个 `key` 是小写折叠过的，取 `key` 永不命中。

9. **「别名」只指 `aliases`。** `title` 是笔记自称，不是别名。两者都走 `reads.otherNamesFor`，
   搜索面两种都算。hover 分两行，引导词用属性名本身（`recentFiles.title` / `.aliases`），
   **小写**、中英文一致。→ detail §64

10. **重画成本几乎全是 DOM**（随行数线性增长）⇒ 只做「少画几次」「别全量重建」。
    **memo / 脏标记 / 合并重画都别做**，得不偿失。→ detail §27

11. **落地行为变了 ⇒ 改使用层，别顺手改采集层。**
    这是 09-28 踩出来的元规则（用户一度说「落点记录只要行号、不要光标」，试过让
    `readLandingState` 不写 cursor，**纯属多余、已撤**）：`landedLine` = `keyLine ?? st.scroll ?? cursor.from.line`，
    只要 `st` 不空就答得出来 ⇒ **每条 jump 的光标都被使用层重算**，采集层写没写 cursor 根本不影响结果。
    撤掉那笔后 887 个用例全绿。**多写一笔采集只会让两处知识重叠。** → detail §56

12. **`armLandingMark` 只有一个 arm 点** —— `execute()` 开头。
    跨 pane / 跨 tab / 原生 delegate / 同文件 apply，**每个分支落到的都是这一条自带的位置**；
    放在某一个分支里就会漏掉另外几个（第一版放在两处，仍漏了「跨 tab 重新激活原叶」那条经 `openInLeaf` 的路）。
    同理 `pendingLineFlash` 带 `at` **到期作废**。→ detail §56

## 2. 动 `src/position/restore/` 之前

- **光标要两个模式都放**。阅读模式放完切回编辑，光标就在那儿（见 §1.1 / §1.2）。
- **`holdEdge` 必须在 `syncViewScroll` 之前完成**（bracket 内的顺序是硬的）。
- **`src/position/restore/pixels.ts` 的三段结构**：先 `settleSourcePixels`（遮罩揭开**前**）→ 再 `relandSourcePixels`
  （揭开**后**的一次性检查）→ 然后**第二阶段**收敛验证。**最多 2 次纠正**，超了就不动。
  `HOLD_MAX_MS` = 400ms、`HOLD_CORRECTIONS` = 2（`src/position/edges.ts:17-18`），
  监听 `pointerdown/touchstart/wheel/keydown`（capture + once）；`el.isConnected` 为假即停。→ detail §61、§14
- **读 scroll 有三级，别混用**：①回读 / 校验 / 重落 + poll ⇒ 实时 `getScroll()`；
  ②导航 `readNavEntryState` ⇒ DOM 不在 layout 时才用 `view.scroll`（own 字段，须 cast）；
  ③desktop 的 `onScrollCapture` ⇒ `readSampledState`。
  **移动端 scroll 事件会丢 ⇒ 任何路径都不许用缓存值。** → detail §34
- **坐标两套，都是行号**：列表显示「当时」的值，**要打开笔记必须先 `nowLineFor` 换算**。
  `st.scroll` 是**视口顶那一行的行号**（0 起算），**不是像素**。
  换算链：mtime 闸门 → anchor → live editor → 磁盘文本。
  ⚠️ **`getScroll()` 不是整数**：它给 0-based 顶行行号**外加该行已被滚过的比例**（`42.37`
  = 顶端落在第 43 行的 37% 处）⇒ 量化到整行是 `Math.round(getScroll())`，**不是** `+0.5`。
  理由见 `src/position/capture/ephemeral.ts:25`：存小数会逼眼睛重扫断行，高块（图片/嵌入）会恢复出半张图。
  ⚠️ 还有个坑：预览渲染器没跟上时它报的是 **`null` 而不是 `undefined`** ——
  `isNaN(null)` 是 false（会绕过旧守卫）、`Math.round(null)` 是 0（会被读成「文件顶部」），
  所以必须用 `scroll == null || !Number.isFinite(scroll)` 挡。→ detail §3

## 5. 动 `src/recent-files/` 之前

- **落点行的 × 必须交 `placeKey` 集合**，只删 rep 会让另一个把行**立刻画回来**。
  改完自己 `render()`（对话框不订阅）。→ detail §2
- **⚠️ 一次「命中」可以改掉这一行的去处**（2026-10-03 定，`list.ts` 的 `HeadingHit`）：
  一篇笔记**仅因**它的某个小节才在列表上时 —— 判据是 `listing.ts matchedOnlyByOutline`：
  拿掉全篇标题那个通道，这一组再没有一条记录进得来 —— 点击去**那个小节**，而不是这一行
  一贯去的地方。行上印出「小节：X」（`.nav-row-hit`），行走由 `onTravelHeading` 造一条
  `outline:X` 的 jump（与点大纲面板同类，**会记一个落点**；`landings:'none'` 档只跳不记）。
  ⚠️ **改道挂在这一行上、不只是挂在点击上**：`goTo` 一处收口（点击 / 中键 / 重画后按身份
  重找 / Enter / 右键菜单那一项），漏一处就有一半的读者落到别处。
  ⚠️ **判据必须严**：只靠名字 / path / 别名 / 自己那条链就进得来的行**不**改道 —— 搜「周」
  找「周回顾」的读者不该被送进「周报」。
  ⚠️ **落点必须写在 `st` 上，光有 `keyLine` 不算**（2026-10-04 修，`places.ts travelToHeading`）：
  施加一次跳转的那一套读的是 `st`（`stack.ts landingOf` / `armLandingMark`），而一个没有 `st`
  的 jump 会一路回落到位置数据库保存的阅读位置（`patcher.ts` 的 `navLanding ?? store.read(...)`

  可读（撑开吸收窗口的是大纲点击那个采集点，这条路径不经过它），所以它必须自己说出落点。
  ⇔ 因此 `TipContent.matched` 已撤：命中**就是**去处，行上已经印了；悬停只补那条链
  （`headingTrailAtLine`）。→ detail §2
- **`printsLandings` 要 ≥2 条落点才画落点行**（`src/recent-files/browser/list.ts`）⇒
  只有一条落点的笔记（**搜索后几乎全是这种**）与 `landings: 'last'|'none'` 两档都没有落点行，
  **笔记行本身就是那条落点**（`activeRep` 走 anchor ?? 最新）。
  ⇒ 那种形状下**笔记行的 tooltip 必须带上整条链**（`TipContent.trail`，`list.ts fileRow`
  的 `!printsLandings && !hit` 分支）：那一行点下去走的是 `openJump`，链是兑现的承诺。
  纯 visit 与钉选行的点击走普通打开 ⇒ 仍然什么都不说；**改道的那一行**说的是它要去那一节，
  而不是它一贯去的那个地点。→ detail §2
- **`NavEntryState` 现在只有 `anchor` + `mtime` 两个附加字段**（`src/types.ts`）。
  曾经有第三个 `context`（落点下面 4 行正文的快照，只喂搜索与 tooltip），
  **2026-10-03 连同它的搜索面与引文机制一起撤掉** ⇒ `readLandingState` 是
  `readNavEntryState` 的别名（保留名字只为让调用点说明它在记一条**落点**），
  `serializeNavHistory` **不再剥任何东西**，那次 `cursorOnScreen` 强制 layout 也没了。
  **撤它的理由**（三条，按分量）：只有「按 key 跳进某个标题」的落点带着它（`placeRecord` /
  `settle` 只给 jump 写 `st`）；它是几周前的一次快照而笔记一直在被读；无词边界的子串匹配
  进主过滤路径就是一台没有排名的噪音发生器（`pro` 命中 `approve`），而按内容找一篇笔记是
  `Cmd+Shift+F` 的活。⚠️ **别把 `st.context` 加回来** —— 替代品是各标题从 metadataCache
  现查（`reads.ts headingsFor`），体积与笔记长度无关。→ detail §2
- **搜索面有八处，每一处都得能自证**（`list.ts` 的 `printedAt`/`outlineAt` +
  `listing.ts` 的 `navSearchText`）：文件名 · 完整 path · 打印名 · frontTitle + aliases ·
  jump 自己的 key · 视图类型与名字，加**该文件的所有小节标题**。
  ⚠️ **全篇标题只给文件行**（`keepAt` 里 `entry.kind === 'jump'` 判假）—— 落点行印的已经是
  它自己那一节的链，给它全篇的标题只会让「我这一行是哪儿」答不出来。
  ⚠️ 一个 jump 落点被画成文件行、且**没有**改道时（`landings: 'last'|'none'` 或只有一处
  地点），那一行靠 `TipContent.trail` 说它所在那一节（点下去兑现的就是那儿）。改道时改由
  行上的 `.nav-row-hit` 说，悬停补链。全篇标题**现查**（`reads.ts headingsFor`），
  **从不存** —— 体积与笔记长度无关。→ detail §2
- **落点行号吃 `jump.keyLine`（`landedLine`）**，不是 `st.scroll ?? cursor`。
  无 keyLine（标题改名/删掉）才回退。→ detail §2
- **置顶**：只在文件行（**置顶行不带落点子行**）；顺序＝**新钉的放末尾**（⚠️ 不是最前）；
  **不做拖拽**；置顶**不占 cap、不被 trim 淘汰、不被后加的排除规则 prune**；
  存储是 path 列表，**本机本地、不跨设备**。→ detail §15
- **列表只有一个选中项**（`is-selected`）；点击**不留标记**；跳转会挪索引 ⇒
  重画后一律走 `keyOf`。⚠️ **例外：键盘光标按槽位恢复**（group/stack 下标）**不是**身份

- **搜索面只有一处判据**：`src/recent-files/browser/list.ts` 的 `printedAt()`（连同
  `keepAt` 里「全篇标题只给文件行」那半句）。行号不搜、visit 不搜标题链、文件行不显示链
  —— **改道的那一节除外**（它印在行上，因为它就是这一行的去处）。
- **⚠️ 重映射锚点（`st.anchor`）不进搜索面**（2026-10-03 撤，`src/recent-files/browser/listing.ts:244`，
  那段注释把理由写全了）：
  它记的是采集那一刻**视口顶行**的文本，随窗口高度与滚动位置变（换设备必然不同），且常落在标题**之上**；
  命中它之后行与 hover 都答不出为什么在（它从来没被显示在任何地方）。**字段留着** —— 文本变动后靠它
  找回行号是**恢复**路径的事（`remapAnchorLine`）。⚠️ 别拿 `tests/recent-files-browser.test.ts`

  `placeRecord` / `settle` 都只给 jump 写），那种形状不存在。→ detail §2
- **锚点两类不记**：空行 与 分割线（`THEMATIC_BREAK`，`src/position/capture/ephemeral.ts:127`）。

## 8. 面板箭头条（`go-to-top` / `go-to-bottom` 等）

- 契约 = **四动作 + `can*`**。置灰问 **`stack.hasStep`**，命令才用 `canNavigate`。
- **两端都是 keyless visit 步**；已在端点 ⇒ **只补光标、不记步**。
- **底 = 可见窗口末端**（`noteEnd` − 可见高度），**不是最大滚动**。
- 顺序是硬的：**先 `funnel.leave` 再 `visit({forced:true})`**（同一文件内会被去重吞掉 ⇒ 必须 forced）。
  写下来处在前，否则随后到的 visit 会把自己当成「离开的那一步」改写掉。→ detail §61
- ⚠️ **`holdEdge` 生效的那 400ms 里 `funnel.moving` 为真 ⇒ `canNavigate` 为假** ——
  断言前先等 500ms。→ detail §61

## 9. 到页顶 / 到页底：`src/position/edges.ts` 三函数

- **`atEdge` / `moveToEdge` / `holdEdge`（`src/position/edges.ts:41` / `:60` / `syncViewScroll:101`）**，
  容差 1px，三者共用。
- **阅读渲染器会把捕获的旧滚动写回去** ⇒ 必须重试（≤2 次 / 400ms）。
- **已经在那一端时：只移动光标，不 leave / visit / hold**（视口没动 ⇒ 一对「看着都没反应」的按压）。
  但**仍要 bracket**（桌面 teleport 推断只看行差、不看 `hasUserIntent`）。→ detail §61

## 10. 怎么验证没坏

**① 先跑测试**（用例数会变，以实跑为准）：

```bash
npx vitest run                            # 全部
npx vitest run tests/note-edges.test.ts   # 只跑你动的那块（edges 改了跑这个）
npx vitest run tests/recent-files-browser-styles.test.ts   # 改了 styles.css 必跑
```

**② 这一篇自己也会坏。** 里面的 `file:line` 引用随代码漂移，而没有任何东西会自动报错 ⇒
改完 `src/**` 顺手跑一次，看有没有引到越界、或者还命中却已经指向隔壁注释的：

```bash
python3 scripts/check-doc-refs.py                       # 全 docs/**
python3 scripts/check-doc-refs.py docs/code-tour/00-改前必读.md
```

退出码 0 只代表「行号没越界」；脚本会把被引的那一句**原样打出来**，
「这一句是不是还在说它被引用时想说的那件事」要你（或 AI）亲眼过一遍。

**③ 验收范围**按 `AGENTS.md` §6 分档，底线是不能让 CI 挂：动了 `src/**` 代码 ⇒ 全套
（两份 `tsc` → `eslint .` → `vitest run` → `npm run build`）；只改注释 / `docs/**` ⇒ 不必跑 build。
想证明「这次真的只动了注释」用 `python3 scripts/check-comment-only.py <文件…>`（退出 0 = 全落在注释上）。
