# 00 改前必读：动手之前先看这里

`01`~`06` 讲**这段代码在干什么**；这一篇讲**动了会坏什么**。两者是不同的问题：
读懂了代码不代表知道它的约束从哪来。

- 只读代码、想弄明白机制 → 读 `01`~`06`，按目录顺序。
- **准备动手改** → 先在这一篇里查你要动的模块，然后去看它指的那一节。
- 想知道「当初为什么这么定」 → 顺着每条规则后面的 `→ detail「节名」` 去 AI 记忆
  （`MEMORY-detail.md`，真身在 Obsidian vault，**不进 git**）；引号里就是那边的章节标题。
  ⚠️ **读不到那边的东西不影响动手**：那边只装 WHY 与实测，这一篇里的判据是完整自洽的。

**每一条规则后面都带可 cmd+click 的源码链接**（形如 `` [`符号名`](/src/foo.ts#L120) ``）——
行号会随代码漂移，§9 有一条命令批量复查，唯一定义的符号还能 `--fix` 自动刷新。

## 1. 十二条最常踩的

按「踩了会静默坏掉」排序，不按模块排。

1. **阅读模式没有「可显示的光标」，但 `editor` 一直在。**
   `MarkdownView.editor` 恒存在（`setMode` 只搬 `scroll` + `fold`，**从不碰 selection**）⇒
   阅读模式 `setCursor` 是有效的。[`cue.ts:114`](/src/position/ui/cue.ts#L114) 附近那句「阅读模式没有光标，所以永远用
   最顶上那个已渲染的块」只对了一半（它谈的是**渲染出来的块**，不是 `editor` 对象）——
   **照它写的 `getMode()` 守卫是错的**。→ detail「到页顶 / 到页底」

2. **切模式 / resize 会把落点打回**（`2be6916`，手机 + 电脑都复现）。
   根因在 app：`setMode(e){ i=this.scroll; … e.setEphemeralState({scroll:i}) }` 携带的是
   **own 字段 `view.scroll`** 而非 DOM；填它的是 `syncScroll()`，而**阅读模式的 `onScroll` 有
   100ms 渲染门** ⇒ 我们直接写 `scrollTop` 永远进不去。
   **修法只有一条路**：`syncViewScroll(view)` 在 `holdEdge` 之后（bracket 内）调
   `view.setEphemeralState({scroll})` —— 与 `setMode` 同一扇门。
   ⚠️ 别对阅读模式做「读 DOM 再写回去」。→ detail「到页顶 / 到页底 · 切模式」

3. **编辑模式下别去 `scrollIntoView` 光标** —— core 自己在 `setState` 时还原原滚动，你那样做会打架。

4. **`leaf.id` 跨会话稳定。** 布局序列化带着 id，重启后恢复出来的每个标签页还是原来那个 id。
   ⇒ 持久化的 `entry.leafId` 重启后仍指得着那个标签页。
   ⚠️ **别加「重启后按 path 找 leaf」的兜底** —— 会盖掉「回到它当时所在的那个标签页」这条刻意语义。→ detail「视图条目」

5. **`FileView` 没有 `file` 不算目的地**，否则删文件那一瞬会铸出 `view:markdown` 幽灵行。
   ⚠️ 别用「什么不是地点」那道黑名单（[`NON_DESTINATION_VIEW_TYPES`](/src/nav/entry.ts#L82)）堵
   —— 那道门与栈共用。→ detail「视图条目」

6. **这份列表只装笔记，不装位置**（2026-10-05 起）。一次 `jump`（大纲点击 / 标题链接 /
   搜索命中）在 `remember` 里**一律降级成 `visit`**（[`remember()`](/src/recent-files/places.ts#L219)），
   所以**一条记录 = 一行**，身份就是它的 path（无路径视图是它的视图类型，`navGroupKey`），
   **没有第二套身份**（`placeKey` 已删）、**没有第二个池子**。
   ⇒ **一落点 = 一记录 / `absorbSameLanding` / `forgetLanding` / `landingKeys` 都随它一起走了。**
   落点没有丢：它在**前进/后退栈**里（`NavStack` 照记 jump、且带 `st`）。→ detail「方案 0」

7. **搜索 / 块引用命中的跳转不进最近文件**（降级成 visit），**但后退栈照记**。
   规则只写在 `NavPlaces` —— funnel / stack / patcher **不动**。判据共享在 `src/nav/entry.ts`
   （[`isCallerKey`](/src/nav/entry.ts#L124) / [`isBlockKey`](/src/nav/entry.ts#L161) / [`blockAnchor`](/src/nav/entry.ts#L145) / [`stripLinkAlias`](/src/nav/entry.ts#L132)），
   别再手写 `startsWith('caller:')`。→ detail「带键跳转的链接文本」、「方案 0」

8. **`prop[: value]` 只认自有属性**（`hasOwnProperty`）。用 `in` 会让 `toString` / `constructor`
   命中每一篇笔记。⚠️ 别用 `Object.hasOwn`（tsconfig 的 lib 是 es2021）。
   **属性名区分大小写**；选择器要取 `getAllPropertyInfos()` 的 **`values().name`** ——
   那个 `key` 是小写折叠过的，取 `key` 永不命中。

9. **「别名」只指 `aliases`。** `title` 是笔记自称，不是别名。两者都走 `reads.otherNamesFor`，
   搜索面两种都算。hover 分两行，引导词用属性名本身（`recentFiles.title` / `.aliases`），
   **小写**、中英文一致。→ detail「hover 上的名字」

10. **重画成本几乎全是 DOM**（随行数线性增长）⇒ 只做「少画几次」「别全量重建」。
    **memo / 脏标记 / 合并重画都别做**，得不偿失。→ detail「面板重画」

11. **落地行为变了 ⇒ 改使用层，别顺手改采集层。**
    这是 09-28 踩出来的元规则（用户一度说「落点记录只要行号、不要光标」，试过让
    `readLandingState` 不写 cursor，**纯属多余、已撤**）：`landedLine` = `keyLine ?? st.scroll ?? cursor.from.line`，
    只要 `st` 不空就答得出来 ⇒ **每条 jump 的光标都被使用层重算**，采集层写没写 cursor 根本不影响结果。
    撤掉那笔后 887 个用例全绿。**多写一笔采集只会让两处知识重叠。** → detail「跳到标题」

12. **`armLandingMark` 只有一个 arm 点** —— `execute()` 开头。
    跨 pane / 跨 tab / 原生 delegate / 同文件 apply，**每个分支落到的都是这一条自带的位置**；
    放在某一个分支里就会漏掉另外几个（第一版放在两处，仍漏了「跨 tab 重新激活原叶」那条经 `openInLeaf` 的路）。
    同理 `pendingLineFlash` 带 `at` **到期作废**。→ detail「跳到标题」

## 2. 动 `src/position/restore/` 之前

- **光标要两个模式都放**。阅读模式放完切回编辑，光标就在那儿（见 §1.1 / §1.2）。
- **`holdEdge` 必须在 `syncViewScroll` 之前完成**（bracket 内的顺序是硬的）。
- **`src/position/restore/pixels.ts` 的三段结构**：先 `settleSourcePixels`（遮罩揭开**前**）→ 再 `relandSourcePixels`
  （揭开**后**的一次性检查）→ 然后**第二阶段**收敛验证。**最多 2 次纠正**，超了就不动。
  `HOLD_MAX_MS` = 400ms、`HOLD_CORRECTIONS` = 2（[`edges.ts:17`](/src/position/edges.ts#L17)），
  监听 `pointerdown/touchstart/wheel/keydown`（capture + once）；`el.isConnected` 为假即停。→ detail「到页顶 / 到页底」、「面板重画」
- **读 scroll 有三级，别混用**：①回读 / 校验 / 重落 + poll ⇒ 实时 `getScroll()`；
  ②导航 `readNavEntryState` ⇒ DOM 不在 layout 时才用 `view.scroll`（own 字段，须 cast）；
  ③desktop 的 `onScrollCapture` ⇒ `readSampledState`。
  **移动端 scroll 事件会丢 ⇒ 任何路径都不许用缓存值。**
- `st.scroll` 是**视口顶那一行的行号**（0 起算），**不是像素**。「当时 → 现在」的重锚
  只剩栈与恢复这一条路：[`resolveAnchorLine`](/src/position/restore/anchor.ts#L42)
  只在前进 / 后退 / 跳转的那次 apply 上跑（标题 / 块 id 结构化锚点，解不出由调用方退回
  文本片段 remap）。最近文件列表**不做任何换算**，行号直接取位置数据库（见本文 §5
  「一行的行号只有一处来源」）—— 旧的 mtime 闸门 → live editor → 磁盘文本三级链
  已随 `now-line.ts` 于 2026-10-05 撤掉，别加回来。
  ⚠️ **`getScroll()` 不是整数**：它给 0-based 顶行行号**外加该行已被滚过的比例**（`42.37`
  = 顶端落在第 43 行的 37% 处）⇒ 量化到整行是 `Math.round(getScroll())`，**不是** `+0.5`。
  理由见 [`ephemeral.ts:25`](/src/position/capture/ephemeral.ts#L25)：存小数会逼眼睛重扫断行，高块（图片/嵌入）会恢复出半张图。
  ⚠️ 还有个坑：预览渲染器没跟上时它报的是 **`null` 而不是 `undefined`** ——
  `isNaN(null)` 是 false（会绕过旧守卫）、`Math.round(null)` 是 0（会被读成「文件顶部」），
  所以必须用 `scroll == null || !Number.isFinite(scroll)` 挡。

- **判「笔记 vs 视图」用 [`isDeferredLeaf`](/src/shared/leaf.ts#L98) + blob 的 `file`**，

- **三个会伪装的视图类**（都不是 FileView 却答得出问题的地方，或反之）：`GD` DeferredView /
  `XD` unknown pane（**类型无工厂时的替补**，`Set(['empty'])` 黑名单拦不住）/ `Z1` 一系面板
  （继承 FileView 但构造翻牌 `navigation=false`）。
  ⚠️ 判据候选里最优雅的一条是 `app.viewRegistry.getViewCreatorByType(viewType)` 为空 ——
  与 Obsidian 自己建视图用的是同一张表。→ detail「视图类型全景」
- **解 `obsidian.asar` 的手法**（查 app 行为时直接抄）：header 的 `jsonLen = uint32 at 12`，
  数据区从 `16 + jsonLen` 起；文件 `offset`/`size` 是**字符串**。→ detail「asar 解包配方」
- **`on('quit')` 拿到的 `Tasks`**：写库 promise 交给 `tasks.addPromise()`，app 才会等它落地。
  ⚠️ **交给 Tasks 的 promise 必须 settle** —— core 在 `Promise.all` 之后才关窗，
  一个 reject 就卡在「Saving…」（`storePositionData()` 要整包 try/catch）。
  三个 localStorage store 是**同步**写。**suspend flush 拿不到 Tasks。** → detail「记忆库的退出与 Tasks」

## 8. 面板箭头条（`go-to-top` / `go-to-bottom` 等）

- 契约 = **四动作 + `can*`**。置灰问 **`stack.hasStep`**，命令才用 `canNavigate`。
- **两端都是 keyless visit 步**；已在端点 ⇒ **只补光标、不记步**。
- **底 = 可见窗口末端**（`noteEnd` − 可见高度），**不是最大滚动**。
- 顺序是硬的：**先 `funnel.leave` 再 `visit({forced:true})`**（同一文件内会被去重吞掉 ⇒ 必须 forced）。
  写下来处在前，否则随后到的 visit 会把自己当成「离开的那一步」改写掉。→ detail「到页顶 / 到页底」
- ⚠️ **`holdEdge` 生效的那 400ms 里 `funnel.moving` 为真 ⇒ `canNavigate` 为假** ——
  断言前先等 500ms。→ detail「到页顶 / 到页底」
- 三个函数签名：[`atEdge`](/src/position/edges.ts#L41) / [`moveToEdge`](/src/position/edges.ts#L60) / [`holdEdge`](/src/position/edges.ts#L69)，容差 1px，三者共用同一个 `edgeTarget`。

## 9. 怎么验证没坏

**① 先跑测试**（用例数会变，以实跑为准）：

```bash
npx vitest run                            # 全部
npx vitest run tests/note-edges.test.ts   # 只跑你动的那块（edges 改了跑这个）
npx vitest run tests/recent-files-browser-styles.test.ts   # 改了 styles.css 必跑
```

**② 这一篇自己也会坏。** 里面的源码链接随代码漂移，而没有任何东西会自动报错 ⇒
改完 `src/**` 顺手跑一次：

```bash
npm run check:docs                                      # 全 docs/**
python3 scripts/check-doc-refs.py docs/code-tour/00-改前必读.md
python3 scripts/check-doc-refs.py --fix                 # 符号的唯一定义行漂移了就直接改文档
```

查三样：链接目标不存在 / 行号越界；链接文字是符号名时，它的唯一定义行与 `#L` 对不上；
旧写法（反引号包着的 `file:line`，cmd+click 跳不了）。退出码 0 只代表这三样都没犯 ——
脚本会把被引的那一句**原样打出来**，「这一句是不是还在说它被引用时想说的那件事」
要你（或 AI）亲眼过一遍（同名定义多处时机器不下判语，也靠这一步）。

**③ 验收范围**按 `AGENTS.md` §6 分档，底线是不能让 CI 挂：动了 `src/**` 代码 ⇒ 全套
（两份 `tsc` → `eslint .` → `vitest run` → `npm run build`）；只改注释 / `docs/**` ⇒ 不必跑 build。
想证明「这次真的只动了注释」用 `python3 scripts/check-comment-only.py <文件…>`（退出 0 = 全落在注释上）。
